# System patterns

Document **architecture** and **recurring patterns** so Copilot stays aligned.

- **High-level layout** (modules, services, boundaries):
- `btq-node/` — **canonical L1** (`l1_mainnet.py`) for BRAHMNETWORK. JSON-RPC (default bind 127.0.0.1:8545); Dilithium3 spends; integer units; Sentinel P2P 18545. RPC method names stay `brah_*`. Public explainer is `GET /` from `btq-node/static/`. `GET /claim` and `/status` serve the same `index.html`; `site.js` opens the join view and reads `?ref=` (app deep link stays `brahm://claim`). `POST /` is RPC.
- `wallet-android/` — Compose wallet (`com.brahmnetwork.wallet`) with inlined `com.brahmnetwork.wallet.sentinel` DTN client. Display coin: Brahma. New addresses: `BRM1G`. Legacy: `BTQ1G`. One wallet password (PBKDF2-HMAC-SHA256 AES-GCM verifier in EncryptedSharedPreferences; the password itself is never stored) gates send, burn, lock-on-open, extra wallets, and mnemonic reveal. New L2 launches are closed (no burn-to-launch). Settings: `lock_on_open` and `send_lock`. Relock in `MainActivity.onStop` unless a configuration change. Do not use biometric/`Continue` as a send bypass. `FLAG_SECURE` on the activity. Release RPC URLs must be `https://` on `brahmnetwork.com` (or the baked public host); debug may use private LAN HTTP. Recovering a phrase while Home already has an identity **adds** a vault slot (up to 60). It does not replace the on-screen first/placeholder wallet. Extra wallets that are not first cannot add. App recovery phrases are not BIP-39 and are not genesis Dilithium hex.
- `btq-data/` — live operator state (`BRAH_DATA_DIR`). Not consensus source. Do not rewrite live `BTQ1G` balance keys.
- `polymarket-hft/` — isolated Polymarket paper engine (FastAPI 8787). Set-builder structural loop + gated directional composite. No shared process, port, env, or ledger with the L1. CLOB V2 via `polymarket-client`; paper CTF merge only.
- **Data flow**: Wallet prefers LAN RPC when the phone IP is `192.168.168.*`, then public HTTPS (`https://www.brahmnetwork.com`), then USB. If RPC is down after one successful account cache, mine/join still sign locally and gossip `TRANSACTION` over Sentinel (LAN TCP 18545, Bluetooth RFCOMM, Wi-Fi Aware). A node that hears that packet runs `commit_signed`. Share/claim stays operator LAN or a real named HTTPS host — never trycloudflare. Payment is sealed only after `brah_submitTx` or mesh ingest. Competing tips at the same height reorg by work then hash. Same-host replica is catch-up, not a second operator. Same pubkey body under `BRM1G` or `BTQ1G` is one account (`resolve_balance_key`).
- **Public TLS**: keep `www.brahmnetwork.com` Cloudflare-proxied with Universal SSL. Daily `check_public_tls.py` is the stall alarm (21-day floor). Do not upload a custom cert dated 2100.
- **Patterns to follow**: `to_units()` converts **Brahma amounts** only (1e8). Genesis L2 coins (ids 1–8) are **whole token units** — do not run them through `to_units` / `from_units`. Mine PoW header reward is `mine_payout_units(state, miner)` (schedule + one-time first-mine +1). L2 operator grant and halving airdrops are idempotent flags on state (`l2_operator_grant_done`, `l2_halving_band_paid`). Canonical message prefix stays `BTQ1|`. Mesh prefixes stay `BTQINVITE` / `BTQHELLO` / `BrahF`.
- **Patterns to avoid**: Treating Sentinel gossip as a sealed paid block. Hardhat / Foundry / unfinished Rust as consensus. Dollar prices. BIP-39. Owner pause/mint. Wiring Ethereum RPC aggregators (dRPC, Infura, etc.) as if they were this L1. Rewriting live `BTQ1G` keys to `BRM1G`. Changing `applicationId` (orphans the installed app).
